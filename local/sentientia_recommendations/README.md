# local_sentientia_recommendations — Sentientia LMS AI Course Recommendations

Tier 1 AI feature #5. Learners see the top 3-5 personalised course
recommendations on their dashboard, generated by Anthropic Claude from
their completion history, current skills, role, and per-tenant learning
patterns. Every recommendation carries a short rationale a learner can
review ("Why this?").

**Status:** Phase H.0 — MVP scaffold. Feature flag default OFF.
Mock-mode demoable end-to-end without spending money.

See [ADR-015](../../docs/adr/ADR-015-ai-recommendations-engine.md) for the
architecture record and
[state card](../../state-cards/local_sentientia_recommendations-state.md)
for current status + open questions.

## How it works

1. **Manager submits the generate form** (`generate.php`) for a target
   learner. Four gates are checked: feature flag ON, `:generate`
   capability, per-customer daily token cap not exceeded, and the
   "I confirm I want to call Anthropic" checkbox (the [CONFIRM] gate).

2. **The engine builds a profile + candidate list.**
   `recommendation_engine::build_profile()` reads the learner's role +
   tenant + completed course IDs. `build_candidate_list()` returns the
   visible catalogue minus already-completed courses.

3. **The pipeline dispatches to mock or live.**
   `anthropic_client::generate()` inspects the
   `sentientia.recommendations.live_api` flag. OFF → deterministic mock.
   ON → real POST to api.anthropic.com.

4. **Response is parsed.**
   `response_parser::parse()` decodes strict JSON, drops malformed items,
   and drops any `course_id` not in the candidate catalogue (Claude
   cannot invent courses).

5. **Batch persists.**
   `recommendation_engine::persist_batch()` expires the learner's prior
   active batch and inserts one row per recommendation with
   `status='active'`.

6. **The learner sees them.** The `block_sentientia_recommendations`
   dashboard block calls `latest_for_user()` and renders the top N with
   score badges + "Why this?" rationale + "Not interested" dismiss links.

## Configuration

| Setting | Where | Default | Notes |
|---------|-------|---------|-------|
| Master flag `sentientia.recommendations.enabled` | Switchboard | OFF | Hides everything |

| Max history items | Site admin | 50 | Completions fed into prompt |
| Per-customer daily token cap | Site admin | 2,000,000 | Resets at midnight |

## Cost model

When `sentientia.recommendations.live_api` is ON, every batch charges
Anthropic per token. Rough sizing:

- Profile + 100-course catalogue ≈ 3,000 input tokens
- 5 recommendations ≈ 500 output tokens
- Sonnet 4.6 price: ~$0.003/1K input + ~$0.015/1K output
- Cost per batch: ~$0.02

A per-customer daily cap of 2,000,000 tokens ≈ ~600 batches per day,
shared across the whole customer.

## Multi-tenant isolation

Every recommendation row carries:
- `customerid` — Sentientia LMS customer scope (Phase 1: hardcoded 1).
- `costcenterid` — BizLMS tenant root from the learner's `open_path`
  at generation time (1, 77, 177, ...).

The dashboard block only ever calls `latest_for_user($USER->id)`, so a
learner only sees their own recommendations. `update_status()` enforces
an ownership check before flipping any row's status.

## Privacy / GDPR / DPDP

`classes/privacy/provider.php` declares the `recommendations_log` table
and the external Anthropic API as a subsystem we transmit an anonymised
learner profile to (only when the live-API flag is ON). The profile sent
to Anthropic is role + tenant + completed course IDs + skill tags — no
names, emails, or employee IDs. Export + delete flows are wired through
Moodle's privacy API.
