## Mission

Tier 1 priority #4 on the Sentientia LMS roadmap. Course Authors paste
source content (SCORM transcripts, narration text, SOP excerpts) and
get a multichoice quiz draft generated by Anthropic Claude. Every
draft passes through a mandatory human-review gate (approve / edit /
reject per question) before approved questions can be pushed to a
`mod_quiz` activity.

## Architecture decision

See [ADR-012](../docs/adr/ADR-012-ai-quiz-generation.md) for the full
record. Highlights:

- **Model:** `claude-sonnet-4-6` default; configurable per draft.
- **Prompts:** Versioned in code (`prompt_builder::VERSION = 'v1'`).
- **Cost gating:** 4 layers (master flag + live-API flag + per-call
  [CONFIRM] checkbox + per-user daily token cap).
- **Mock mode:** When `sentientia.aiquiz.live_api` is OFF (default), the
  entire pipeline runs against a deterministic mock client — zero spend,
  end-to-end demoable.
- **Parser:** Strict JSON contract; silently drops malformed items.
- **Multi-tenant:** Standard Sentientia LMS `customerid` + `costcenterid`
  conventions. `load_for_actor()` rejects cross-tenant draftid guessing.

## Database schema (2 tables — locked in Phase G.0)

| Table | Rows per | Purpose |
|-------|----------|---------|
| `local_sentientia_aiquiz_draft` | one per generation request | Owner, source text, model, prompt version, token usage, status lifecycle (pending → generated → approved/rejected → pushed/failed), reviewer audit |
| `local_sentientia_aiquiz_question` | one per generated question (FK to draft) | qtype, qtext, qoptions_json, qanswer (index), qexplanation, sortorder, reviewer status (generated → approved/edited/rejected) |

| Capability | Roles allowed | Notes |

| `local/sentientia_aiquiz:review`   | editingteacher+, manager | Approve / edit / reject questions |
| `local/sentientia_aiquiz:manage_all` | manager | See + review every draft across all owners |

## Feature flags

| Flag | Default | Purpose |
|------|---------|---------|
| `sentientia.aiquiz.enabled` | **OFF** | Master switch. Pages return 403 when OFF. |
| `sentientia.aiquiz.live_api` | OFF | When OFF, calls go to deterministic mock client. When ON, real POST to api.anthropic.com. |
| `sentientia.aiquiz.auto_push` | OFF | When OFF, "Push approved to course quiz" button is disabled. |

## Admin settings (Site admin → Plugins → Local plugins → AI Quiz)

| Key | Type | Default | Notes |
|-----|------|---------|-------|
| `api_key` | passwordunmask | (empty) | Anthropic API key. Required only when `live_api` flag is ON. |
| `default_model` | text | `claude-sonnet-4-6` | Model identifier. |
| `max_questions` | int | 10 | Per-request question count ceiling. |
| `daily_token_cap` | int | 500000 | Per-user/day soft cap (input + output). |
| `max_source_words` | int | 4000 | Reject sources longer than this. |

## Open questions for Nitin

- **Anthropic budget approval.** Need a signed-off monthly cap before
  flipping `sentientia.aiquiz.live_api` to ON in production. Current
  default of 500k tokens/user/day × 50 active trainers × 25 days × $0.003/
  ~1k input tokens = ~$1,875/month worst case. Suggested initial cap:
  $500/month (one tenant), then expand per-customer.
- **Real `mod_quiz` push.** G.4 is unblocked once the push pipeline ships;
  in the meantime the button is wired but writes `pushed_quizid=0` and the
  draft cannot be re-pushed. Acceptable for G.0?
- **Two-person review.** Some compliance frameworks require a second
  reviewer before deploying generated questions. Default OFF; gated behind
  a future `sentientia.aiquiz.two_person_review` flag if needed by any
  customer.
- **PII heuristic strength.** Currently catches Aadhaar + PAN only. Names
  / emails / employee IDs pass through. Real DLP scan deferred to G.2
  alongside PDF upload. Is the current heuristic enough for Public-tenant
  first run?
