## Real bugs UAT surfaced — all fixed in this session

### Bug 1: Featured widget never rendered on dashboard
- **Symptom**: 4 Tier-1 cases failed (T1.1.a-d) — widget heading missing,
  no cards rendering even though 3 rows were pinned in the DB.
- **Root cause**: `theme/airpayux/layout/dashboard.php` called
  `function_exists('local_airpay_courses_render_featured_widget')` but
  the lib.php was never `require_once`'d. Moodle's setup.php only
  autoloads `/local/*/lib.php` for some entry points, not theme layouts.
- **Fix**: Explicit `require_once($CFG->dirroot . '/local/airpay_courses/lib.php')`
  before the function_exists check.

### Bug 2: Featured admin page 500ed with SQL error
- **Symptom**: `/local/airpay_courses/featured.php` returned a database
  exception — `Unknown column 'name' in 'SELECT'` on `local_airpay_org`.
- **Root cause**: I queried `SELECT id, name FROM {local_airpay_org}` but
  the table uses `fullname`, not `name`. The whole admin page was
  broken — admins couldn't curate featured courses.
- **Fix**: Changed query to `SELECT id, fullname` + use `$o->fullname`.

### Bug 3: 8 hardcoded `/local/...` URLs broke on non-root installs
- **Symptom**: Tier-4 evaluations probe surfaced
  `http://localhost:8080/local/airpay_evaluation/import_template.php` —
  missing the `/moodle/` prefix because the link was hardcoded with a
  leading `/`. This XAMPP runs at `/moodle/`, so all these links 404.
- **Files affected** (all my code from yesterday's stretch):
  - `airpay_courses/templates/manage.mustache` × 2 (Featured + Mass enrol)
  - `airpay_users/templates/manage.mustache` × 2 (Bulk status + Import CSV)
  - `airpay_users/templates/profile.mustache` × 1 (Change photo)
  - `airpay_skills/templates/manage.mustache` × 2 (Designation + Course mapping)
  - `airpay_evaluation/templates/manage.mustache` × 1 (Import template)
  - `airpay_evaluation/templates/questions.mustache` × 1 (Export template)
- **Fix**: All 9 routed through `moodle_url::out(false)` context vars in
  the corresponding `*.php` entry points. The Mustache template uses
  `{{{ xxx_url }}}` for the resolved URL.
- **Impact**: Without this fix, EVERY click on these "admin extra" links
  would 404 in production (live.airpay.academy isn't at `/`).

### Bug 4: A11y regression on now-rendering featured widget
- **Symptom**: After fixing Bug 1, the widget started rendering on
  `/my/dashboard.php` — and the a11y harness flipped from green to
  1 critical + 1 serious.
- **Root causes**:
  - `<span class="badge bg-primary">` — Bootstrap 5's `bg-primary` doesn't
    auto-set text color. Default `#1d2125` text on `#0066a7` blue =
    **2.66:1**, fails WCAG AA 4.5:1.
  - `<code class="small text-muted">` and `<p class="small text-muted">`
    in the widget cards — `text-muted` = `#6a737b` on `#f2f4fb` =
    **4.39:1**, also fails AA.
  - `btn-outline-secondary` `Preview` link — same 4.39 ratio.
- **Fix in `featured_widget.mustache`**:
  - Badge: explicit `text-white` class
  - Muted text + outline button: inline
    `style="color: var(--ap-text-secondary, #5a6070)"` (= 6.96:1)
- **Also**: button-name a11y violation on featured.php — `+` button had no
  accessible name. Fixed: added `aria-label="Add featured course mapping"`
  + `aria-hidden="true"` on the icon.

## What this session proved

The 16 commits from 2026-05-08 are functionally correct — every CRUD
operation, smoke test, and workflow harness was green. **But** Nitin's
gut was right that things weren't "actually working" — 4 real,
user-visible bugs only surfaced when the UI was driven end-to-end:

- Widget that never rendered (lib.php autoload assumption)
- Admin page that 500ed on every load (wrong column name)
- 9 links that 404'd on the production-style URL layout
- 12 a11y nodes that violated WCAG AA on the now-rendering widget

The automated harnesses didn't catch these because:
- **Smoke tests** import PHP directly; they don't go through HTTP/router/cache
- **Workflow harness** loads pages but didn't follow the cross-page link
  click → 404 path
- **A11y harness** scanned the pages but the widget was empty before, so
  the contrast violations didn't exist yet

UAT-driven walkthrough is what made these visible. Worth ~3h of session
time to upgrade trust from "code is shipped" to "code actually works".
