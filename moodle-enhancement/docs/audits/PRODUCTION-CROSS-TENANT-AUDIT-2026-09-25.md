# Production cross-tenant audit - airpay.academy (BizLMS 4.1.2) - 2026-09-25

**Status: READ-ONLY audit. Nothing was changed on production or in the production codebase.**
Codebase: `D:/Claude Local/Moodle Backup/01-production-codebase/html` (snapshot of the eAbyas BizLMS
fork that runs https://www.airpay.academy), cross-checked against the later patches in
`02-enhancement-code` and the 2026-04-17 production DB import (role/capability rows only).

Method: the same defect classes ADR-031 fixed in Sentientia (unscoped capabilities default-granted to
an archetype; plugin capabilities that skip the tenant filter; fail-open when a tenant does not resolve;
writes that never check the target's tenant; privilege escalation). Sweeper agents per partition, then
one adversarial skeptic per finding that re-read the code and tried to refute it.

**Result:** 42 findings reported; 37 CONFIRMED, 0 UNCERTAIN, 5 REFUTED. Of the confirmed/uncertain: 24 P0, 11 P1, 2 P2 (severity is a first-pass heuristic from the defect class and who can reach it - review before triage).

> **Partition 3 is NOT covered yet** (onlineexams, evaluation, notifications, skillrepository,
> biz_cart, ratings, forum and the BizLMS dashboard/report blocks). Its first run was stopped by a
> safety classifier and the re-run by a session limit; an empty result there does not mean clean.
> Re-run pending.

## What this means

- Several web services and pages in production check only `require_login()` before deleting or
  editing organisation, course, classroom, program, group and user records by id, so **any logged-in
  account** - not just a tenant admin - can reach them. These are the P0 rows below.
- Some list/download paths concatenate request parameters into SQL (`PARAM_RAW`), which is both a
  tenant leak and an injection class.
- The BizLMS scoping helper fails open for users with no `local_userdata` row (1,560 rows vs ~2,871
  users in the April import), so many list pages return every tenant for those users.
- The successor Sentientia product (UAT, Moodle 5.2) replaces these plugins; ADR-031 closes the same
  classes there. Production stays exposed until the cutover or until interim patches ship.

## Recommended interim actions (need Nitin's go - production deploys are gated)

1. **Disable the unauthenticated-capability write services** in production (Site admin > Server >
   Web services > External services: remove the affected functions from the AJAX-enabled service, or
   add a `require_capability` + target-tenant check in each `external.php` method). Highest value, smallest
   change: the P0 delete/edit endpoints.
2. **Parameterise the SQL** in the `PARAM_RAW` concatenations (users download / filters, courses ajax,
   program users) or remove the parameters.
3. **Revoke `local/costcenter:manage_multiorganizations` from every role except the site admin** (it is
   held by role 1 `manager` at system context in the April import; role 9 does not hold it) and audit
   who holds role 1 at system context.
4. **Backfill `local_userdata`** for users without a row, or make the scoping helper fail closed.
5. Treat the Sentientia cutover (ADR-028 track) as the durable fix; do not port these plugins forward.
