| Question-bank translation (illustration) | 677,520 + 1,033,226 = 1,710,746 characters per target language | at an assumed 4 characters per token (assumption for English; Indic scripts usually need more, to be measured in the brief's evaluation): 1,710,746 / 4 = 427,687 tokens per target language, about the same again for output | four translate targets: 4 x 1,710,746 = 6,842,984 characters |

## 7. Gaps the brief must address (facts about the code)

1. No code path for a local or OpenAI-compatible endpoint. Adding one means a new provider branch in
   `gateway.php::call_live` (the single live HTTP path in the gateway) and a pricing or zero-cost entry. The assistant
   (`ai_client::call_claude`), the agent (`agent_client`) and pipeline Agent 2 each carry their own direct HTTP code
   in addition to the gateway.
2. No tokenizer or input-token budget in the gateway; context limits are word caps in the consumers.
3. No quality evaluation for live output; golden tests cover mock text only.
4. No streaming, tool-use API, embeddings, vision or prompt caching in the gateway payload.
5. Translation has no chunking above 4000 words per request.
6. Latency: the HTTP timeout is fixed at 60 s; interactive features are synchronous page requests.
7. No data-residency control in the gateway beyond the provider choice. ADR-034 requires PII scanning and in-India
   processing for the content engine (Planned).
8. Hindi has dedicated prompts (v2-hindi for quiz, skills, authoring). Swahili exists only as a translate target and
   a UI language pack; there are no Swahili prompts.
9. Per-plugin daily caps are checked at page level before the call, not inside the gateway, and the recommendations
   cap counts customer 1 only.
