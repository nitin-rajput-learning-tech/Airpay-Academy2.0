What this proves

Tick 2's rank shift (1 → 8) is a qualifying large-move under message_helper::LARGE_MOVE_THRESHOLD, AND compute_changes() emits it in the event payload, AND the observer reaches message_helper::dispatch(). The only thing stopping the message from being sent is the per-user throttle row — exactly the contract the test_throttle_blocks_duplicate_within_24h test pins in mock mode, here demonstrated as cron output.

The throttle row's last_old_rank and last_new_rank remain frozen at the tick-1 values — the helper only updates the row on a successful message_send() return. That keeps the diagnostic fields accurate for HR forensics.
